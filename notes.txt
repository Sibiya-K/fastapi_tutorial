# Authentication - process of verifying who user is, usuaally through login system
# Like email and password; only authenticated users can access certain parts of your API
# Authorization - after authentication, authorization is what the user is allowed to do e.g. regular
# vs. admin. Authentication - user proves they are user 123; authorization user 123 can view own data
# but cannot delete another user's data. 
# What is JWT, and why use JWT (JSON Web Tokens) - compact token sent by clients to prove they are
# authenticated. Tokens are a signal with a secret key, so the server can verify they haven't been
# tempered with. No server-side session storage is needed - everything needed to verify is inside
# the token. 
# How JWT works - User logs in with creditials > Server verify login and generates a JWT token
# > Client includes this token in the Authorization header for future requests. > Server checks
# token validity before responding. This pater makes scalable and stateless authentication possible
